# 员工职业发展地图

中文纯前端演示项目。主页聚焦当前岗位、同序列向上两级岗位和邻近职级的跨序列探索岗位；三条序列可旋转切换，岗位悬停有程序坞式放大反馈。可比较要求、设置主要目标、收藏技能和岗位、管理学习清单，并切换或编辑四位虚拟员工。所有模拟数据保存在当前浏览器。

## 启动

需要 Node.js 22 或更新版本。进入本目录后：

```bash
npm install
npm run dev
```

开发预览固定使用 `http://localhost:26012/`。

运行 `npm run build` 做类型检查和生产构建，`npm test` 运行比较与持久化逻辑测试。当前版本不含后端、登录、正式审批或真实员工数据。

## 数据来源与映射

- `src/data.ts`：岗位网格与年薪参考，依据开发 Prompt §3 转录的截图表，并与《营拓职级体系及26年拓展绩效解读-TOBP.pdf》第 14 页交叉核对。截图原文件尚未找到。年薪统一显示“万元/年”，保留“+”及缺失口径。
- `src/position-details.json`：岗位定位、职责、结果与范围，来自《营运拓展营拓技能清单-TO庚涛.xlsx》“技能清单”工作表。只关联明确可对应的岗位，其他显示“标准待补充”。
- `src/position-skills.json`：同一工作表中按岗位对应的编码关键技能与完整描述，由 `scripts/extract_position_skills.py` 生成。岗位详情以编码标签展示；未提供编码的通用能力和软性素质标为“未编码”，不补造代码。
- `src/source-data.json`：35 个技能、278 条明确可对应的职级要求、519 个原始矩阵单元格记录。保留原始代码、原文、工作表及单元格。生成脚本是 `scripts/extract_sources.py`；仅在实际合并范围内继承单元格。
- `src/promotion-data.json`：7 条晋升起止职级规则，来自《拓展晋升标准-TO庚涛.xlsx》Sheet1!B11:E14。规则保留提报、周期、次数与通过标准原文。生成脚本是 `scripts/extract_promotion.py`。
- PDF 第 25–26 页与晋升表部分周期/适用范围不同，相关规则仍标记待确认。`src/data.ts` 的 `issues` 集中记录冲突、缺失和当前展示假设。
- 同目录的《A 20261011 营拓人才管理大表格.xlsx》是额外资料，目前保留原件，未覆盖上述四份指定来源的规则；其版本和优先级待确认。

明确可对应的技能矩阵范围：营运 L2–L7、营拓 L3–L7、拓展 L5–L7。其余职级保持空缺或待确认，不做整表职级平移。`/`、空白和 `0` 在 `rawMatrixRows` 中各自保留，未统一解释为“不要求”。“提出判断 / 独立干 / 能带教”仅在原文为同一定义时比较层次。

## 演示行为与未来接入点

`src/data.ts` 中的 `Employee`、`SkillRecord`、`Plan`、`Metric` 是未来员工、认证、发展计划及业务指标接口的数据边界。`src/logic.ts` 为独立纯函数，负责岗位比较、差距、路线及本地持久化恢复；`src/promotion.ts` 负责适用规则和业务指标比较。替换数据服务时保留稳定岗位/技能 ID 与来源引用，并对身份、认证与业务指标分别接入可信接口。

当前员工的认证与业务数字是演示假设。学习状态与正式认证状态分开；业务数值只有在单位、周期、范围与规则完全一致时才比较。岗位浏览、员工当前岗位、主要目标和收藏互不混淆。

岗位详情中的“营运 / 加盟商发展 / 拓展”能力图按技能层次计点：已认证技能按层次计 1–3 点，目标岗位按已确认必备技能的要求层次汇总。绿色代表员工已认证能力点，金色代表当前浏览岗位的目标点；演示认证可在技能详情中一键通过并立即更新图形。岗位无可对应技能标准时，不绘制目标轮廓。图形仅作探索展示，不表示晋升或转岗资格。跨序列岗位只标为“转岗探索”，实际映射仍待确认。

软性素质在岗位介绍中以一段话概述，不进入技能认证、能力差距、岗位差异或提升清单的逐项列表。

## 已知待确认事项

可在“演示设置 → 规则版本与待确认项”查看不同口径和当前展示假设，主要包括营拓 L8/L9 职级错位、带教考察周期、资料准确度过渡期 90% 与正文 100%、Y/S 编码、跨序列岗位映射、高职级细则以及薪酬口径。具体资料出处只保存在代码和此文档中，不展示在网页。未确认的规则不产生正式资格判断。
